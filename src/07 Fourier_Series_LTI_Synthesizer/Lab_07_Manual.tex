\section{Fourier Series: The Mathematical Foundation}
%--------------------------------------------------------------

\subsection{Trigonometric Fourier Series}

Any periodic signal $x(t)$ with period $T$ can be represented as an infinite sum of sines and cosines:
\begin{equation}
x(t) = \frac{a_0}{2} + \sum_{k=1}^{\infty} \left[ a_k \cos(k\omega_0 t) + b_k \sin(k\omega_0 t) \right],
\label{eq:fs_trig}
\end{equation}
where:
\begin{itemize}
    \item $\omega_0 = 2\pi / T$ is the fundamental angular frequency (rad/s).
    \item $k = 1, 2, 3, \ldots$ indexes the harmonics (integer multiples of the fundamental).
    \item $a_0 / 2$ is the DC component (average value).
    \item $a_k$ and $b_k$ are the Fourier coefficients, computed via integration.
\end{itemize}

\noindent
\textbf{Computation of coefficients:}
\begin{align}
a_k &= \frac{2}{T} \int_0^T x(t) \cos(k\omega_0 t) \, dt, \quad k = 0, 1, 2, \ldots \\
b_k &= \frac{2}{T} \int_0^T x(t) \sin(k\omega_0 t) \, dt, \quad k = 1, 2, 3, \ldots
\end{align}

\subsection{Exponential (Complex) Fourier Series}

Alternatively, using Euler's formula $e^{j\theta} = \cos\theta + j\sin\theta$:
\begin{equation}
x(t) = \sum_{k=-\infty}^{\infty} c_k e^{jk\omega_0 t},
\label{eq:fs_exp}
\end{equation}
where the complex coefficient is:
\begin{equation}
c_k = \frac{1}{T} \int_0^T x(t) e^{-jk\omega_0 t} \, dt.
\end{equation}

\noindent
\textbf{Relationship to trigonometric form:}
\begin{align}
a_k &= c_k + c_{-k}^* \text{ (real part)} \\
b_k &= j(c_k - c_{-k}^*) \text{ (imaginary part)} \\
|c_k| &= \frac{1}{2}\sqrt{a_k^2 + b_k^2} \quad \text{(magnitude spectrum)}
\end{align}

\subsection{From Fourier Series to Synthesis (The Inverse Problem)}

\textbf{Analysis:} Given $x(t)$, compute $a_k$, $b_k$ (or $c_k$).

\noindent
\textbf{Synthesis (your task):} Given $a_k$, $b_k$ (or $c_k$), reconstruct $x(t)$ by summing harmonics.

In this lab, you will:
\begin{enumerate}
    \item Hand-calculate the Fourier coefficients for your assigned waveform.
    \item Store these coefficients in your Arduino program.
    \item Generate discrete-time samples by evaluating the Fourier Series at sampled times: $x[n] = \frac{a_0}{2} + \sum_{k=1}^{N} \left[ a_k \cos(k\omega_0 n T_s) + b_k \sin(k\omega_0 n T_s) \right]$, where $T_s = 1/f_s$ is the sampling period.
    \item Send those samples to the DAC (Digital-to-Analog Converter), creating an analog waveform.
    \item Add harmonics one at a time ($N = 1, 2, 3, \ldots$) to watch the waveform converge to your target.
\end{enumerate}

\subsection{The Gibbs Phenomenon}

When you truncate the Fourier Series to a finite number of harmonics ($N < \infty$), the reconstructed signal exhibits \textbf{overshoot and ringing} near discontinuities. This is the \textbf{Gibbs Phenomenon}.

\textbf{Key insight:} No matter how many harmonics you add, overshoot persists at about $9\%$ of the discontinuity magnitude. But the width of the overshoot region shrinks as $N$ increases.

In this lab, you will \textbf{observe} the Gibbs Phenomenon as you add harmonics one at a time—hearing the buzzing/ringing sound at edges, and seeing it on the oscilloscope.

\section{Hardware Setup: The Synthesis Chain}
%--------------------------------------------------------------

\subsection{System Overview}

\begin{enumerate}
    \item \textbf{Arduino PWM/DAC}: Generates a digital representation of your synthesized signal (8-bit or 12-bit).
    \item \textbf{Low-pass filter}: Smooths the digital output to a continuous analog waveform (removes high-frequency switching artifacts).
    \item \textbf{Audio amplifier}: Boosts the weak analog signal to speaker-level (typically 1--2 V at 100 mA).
    \item \textbf{Speaker}: Converts electrical signal to sound.
    \item \textbf{Oscilloscope probe}: Measures the analog waveform after filtering (but before amplification, to avoid loading effects).
\end{enumerate}

\subsection{PWM-to-Analog Conversion}

The Arduino Uno does not have a true DAC. Instead, it uses Pulse-Width Modulation (PWM) on pin D11 at ~490 Hz (configurable). By varying the duty cycle (how long the output is HIGH vs. LOW in each PWM period), you can effectively generate 256 discrete voltage levels between 0 and 5 V.

\textbf{How it works:}
\begin{equation}
V_{\text{out}} = V_{\text{supply}} \times \frac{\text{PWM duty cycle}}{255}.
\end{equation}

A low-pass filter (typically RC circuit with cutoff frequency $\sim 1$ kHz) removes the ~490 Hz PWM carrier and leaves only the slow-moving signal envelope—your synthesized waveform.

\subsubsection*{Generating the Sample Array}

In the \texttt{setup()} function, compute the sample array:

\begin{verbatim}
void setup() {
  Serial.begin(115200);

  // Generate one period of the waveform
  for (int n = 0; n < N_SAMPLES; n++) {
    float sample = a0 / 2.0;  // DC component

    // Add harmonics up to the current number (num_harmonics)
    for (int k = 1; k <= num_harmonics; k++) {
      float harmonic_phase = (2.0 * PI * k * n) / N_SAMPLES;
      sample += a[k] * cos(harmonic_phase);
      sample += b[k] * sin(harmonic_phase);
    }

    // Scale to 0--255 PWM range (assuming signal is normalized to [-1, 1])
    uint8_t pwm_value = (uint8_t)(127.5 + 127.5 * sample);
    waveform_samples[n] = pwm_value;
  }

  // Start the timer interrupt to output samples at FS_HZ rate
  startTimerInterrupt(FS_HZ);
}
\end{verbatim}

The skeleton code handles the timer interrupt and serial output. You only need to fill in the loop that computes \texttt{waveform\_samples[]}.

\section*{Appendix A: Fourier Series Examples and Coefficients}
\addcontentsline{toc}{section}{Appendix A: Fourier Series Examples and Coefficients}

\subsection*{A.1 Square Wave (50\% Duty Cycle)}

For $x(t) = \begin{cases} 1 & 0 < t < T/2 \\ -1 & T/2 < t < T \end{cases}$:

\textbf{Coefficients:}
\begin{align}
a_0 &= 0 \quad \text{(no DC)} \\
a_k &= 0 \quad \text{(no cosines, by symmetry)} \\
b_k &= \begin{cases} \frac{4}{k\pi} & k \text{ odd} \\ 0 & k \text{ even} \end{cases}
\end{align}

\noindent
\textbf{Series:}
\begin{equation}
x(t) = \frac{4}{\pi} \sin(\omega_0 t) + \frac{4}{3\pi} \sin(3\omega_0 t) + \frac{4}{5\pi} \sin(5\omega_0 t) + \cdots
\end{equation}

\subsection*{A.2 Sawtooth Wave}

For $x(t) = \frac{2t}{T} - 1$, $0 < t < T$:

\textbf{Coefficients:}
\begin{align}
a_0 &= 0 \\
a_k &= 0 \quad \text{(odd symmetry)} \\
b_k &= -\frac{2}{k\pi}
\end{align}

\noindent
\textbf{Series:}
\begin{equation}
x(t) = -\frac{2}{\pi} \sin(\omega_0 t) - \frac{1}{\pi} \sin(2\omega_0 t) - \frac{2}{3\pi} \sin(3\omega_0 t) - \cdots
\end{equation}

\subsection*{A.3 Triangular Wave}

For a symmetric triangle peaking at $t = T/4$:

\textbf{Coefficients:}
\begin{align}
a_0 &= 0 \\
a_k &= \frac{8}{\pi^2 k^2} \quad k \text{ odd}, \quad a_k = 0 \quad k \text{ even} \\
b_k &= 0 \quad \text{(even symmetry)}
\end{align}

\noindent
\textbf{Series:}
\begin{equation}
x(t) = \frac{8}{\pi^2} \cos(\omega_0 t) + \frac{8}{9\pi^2} \cos(3\omega_0 t) + \frac{8}{25\pi^2} \cos(5\omega_0 t) + \cdots
\end{equation}

\subsection*{B.1 Changing PWM Frequency}

The default PWM frequency on D11 is ~490 Hz. To increase it for better audio fidelity, reconfigure Timer2:

\begin{verbatim}
// Set PWM frequency on D11 to ~8 kHz
TCCR2B = TCCR2B & 0b11111000 | 0b00000001;  // prescaler = 1
\end{verbatim}

\noindent
Formula: $f_{PWM} = f_{CPU} / (256 \times \text{prescaler})$. For prescaler = 1: $f_{PWM} = 16 \text{ MHz} / 256 = 62.5 \text{ kHz}$ (maximum for 8-bit PWM).

For 8-bit resolution, maximum achievable PWM frequency is ~62 kHz. If you need lower (e.g., 8 kHz), use prescaler 8: $f_{PWM} = 16 \text{ MHz} / (256 \times 8) = 7.8 \text{ kHz}$.

\subsection*{B.2 High-Speed Timer Interrupt}

To output samples at a precise sampling rate (e.g., 10 kHz), use Timer1 interrupt:

\begin{verbatim}
// Initialize Timer1 for sampling rate Fs_Hz
void initSamplingTimer(int Fs_Hz) {
  cli();  // disable interrupts

  TCCR1A = 0;
  TCCR1B = 0;
  TCNT1 = 0;

  // Set compare match register: OCR1A = (16 MHz) / (1 * Fs_Hz) - 1
  OCR1A = (16000000 / Fs_Hz) - 1;

  // Set CTC mode (Clear Timer on Compare Match)
  TCCR1B |= (1 << WGM12);

  // Set prescaler = 1
  TCCR1B |= (1 << CS10);

  // Enable Timer1 compare interrupt
  TIMSK1 |= (1 << OCIE1A);

  sei();  // enable interrupts
}

// Interrupt service routine (called at Fs_Hz rate)
ISR(TIMER1_COMPA_vect) {
  // Output the next sample to PWM
  analogWrite(D11, waveform_samples[sample_index]);

  // Advance to next sample (wrap around at N_SAMPLES)
  sample_index = (sample_index + 1) % N_SAMPLES;
}
\end{verbatim}

The skeleton code provides this; you only need to call \texttt{initSamplingTimer(FS\_HZ)} in setup.

\subsection*{Hardware and Audio Issues}

\begin{enumerate}
    \item \textbf{No sound from speaker, or very quiet sound.}
    \begin{itemize}
        \item Verify the amplifier power supply is on (check voltage at op-amp power pins).
        \item Test with a simple DC test: \texttt{analogWrite(D11, 128)} should produce a steady voltage and quiet hum from the speaker.
        \item Check speaker impedance matching. Some speakers may require a current-limiting resistor (e.g., 8 $\Omega$ speaker with 100 $\Omega$ series resistor to reduce volume).
        \item If oscilloscope shows large signal after filter but speaker is silent, the amplifier may not be powered correctly.
    \end{itemize}

    \item \textbf{Waveform on oscilloscope looks distorted or clipped.}
    \begin{itemize}
        \item Check that the PWM duty cycle is within 1--254 (not 0 or 255, which are extremes).
        \item Verify the low-pass filter cutoff frequency (~1 kHz) is well below your sampling rate. If the cutoff is too low (e.g., 100 Hz), high-frequency harmonics are attenuated.
        \item Clipping may indicate your signal amplitudes are too large. Reduce by dividing the waveform samples by 2 in the synthesis code.
    \end{itemize}

    \item \textbf{Gibbs phenomenon overshoot is very pronounced (>50\% overshoot).}
    \begin{itemize}
        \item This is normal and expected for square/sawtooth/pulse waves! The Gibbs Phenomenon always overshoots by ~9\% of the discontinuity magnitude.
        \item If overshoot is much larger, your signal may be clipping or your coefficients may be wrong.
    \end{itemize}

    \item \textbf{Tone does not change when you add harmonics.}
    \begin{itemize}
        \item Check that your Fourier coefficients for higher harmonics ($k > 1$) are non-zero. If they are all zero, only the fundamental is being synthesized.
        \item Verify the button interrupt is firing: add a Serial print statement in the \texttt{buttonISR()} to confirm \texttt{num\_harmonics} is incrementing.
        \item Ensure \texttt{regenerateWaveform()} is being called and the PWM output is being updated.
    \end{itemize}
\end{enumerate}

\subsection*{Arduino Code Issues}

\begin{enumerate}
    \item \textbf{Arduino does not respond to button press.}
    \begin{itemize}
        \item Verify the button is connected to D2 (INT0 interrupt pin) and the other side to GND.
        \item Use a multimeter to confirm the button makes a connection when pressed.
        \item Add a 10 k$\Omega$ pull-up resistor to D2 (internal pull-up via \texttt{pinMode(D2, INPUT\_PULLUP)}).
        \item Check the interrupt handler is properly registered: \texttt{attachInterrupt(digitalPinToInterrupt(2), buttonISR, FALLING);}.
    \end{itemize}

    \item \textbf{Synthesis loop takes too long; audio glitches or stutters.}
    \begin{itemize}
        \item Avoid floating-point math inside the timer interrupt if possible. Use fixed-point or pre-computed lookup tables.
        \item Reduce the number of harmonics you're computing in real-time. Pre-compute the full waveform in setup(), then just update the samples array.
        \item If \texttt{regenerateWaveform()} is being called in the button interrupt, keep it simple to avoid blocking the timer.
    \end{itemize}

    \item \textbf{Compile error: "multiple definitions of ISR".}
    \begin{itemize}
        \item You've accidentally defined the same interrupt handler twice. Check your code for duplicate \texttt{ISR(TIMER1\_COMPA\_vect)} or \texttt{ISR(INT0\_vect)}.
        \item If using the skeleton, ensure you're not adding your own interrupt handlers where the skeleton already defines them.
    \end{itemize}
\end{enumerate}

\subsection*{MATLAB Analysis Issues}

\begin{enumerate}
    \item \textbf{FFT plot shows very small magnitudes (e.g., all peaks $< 0.01$).}
    \begin{itemize}
        \item Check your normalization. The formula for one-sided spectrum is: $\text{magnitude} = |Y(k)| / (N/2)$ for $k = 1$ to $N/2-1$.
        \item Verify your input samples are in the correct range (e.g., 0--255 for 8-bit ADC). If they're already normalized to $\pm 1$, use a different normalization.
        \item Ensure you're using the correct sampling rate: $f = (\text{sample index}) \times f_s / N$.
    \end{itemize}

    \item \textbf{Empirical FFT doesn't match hand-calculated coefficients.}
    \begin{itemize}
        \item Double-check your hand calculations. Symmetry errors (e.g., missing negative coefficients for exponential form) are common.
        \item Check your Arduino code: are the coefficients correctly entered? Print them to serial for verification.
        \item Noise and ADC quantization will cause small deviations. These are acceptable and expected.
    \end{itemize}

    \item \textbf{Gibbs Phenomenon plot looks strange (no overshoot visible).}
    \begin{itemize}
        \item Ensure your target waveform has a discontinuity (e.g., square wave, sawtooth). Smooth waveforms don't exhibit Gibbs ringing.
        \item Check that your Fourier coefficients are correct. If they're all near-zero, the reconstructed signal will be nearly flat.
        \item Verify the y-axis limits are wide enough to show overshoot: use \texttt{ylim([-1.5, 1.5])} for a signal ideally in $[-1, 1]$.
    \end{itemize}
\end{enumerate}

    \item If the button interrupt is not responding after 10 minutes of debugging.
